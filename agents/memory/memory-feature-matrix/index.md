This matrix compares the thirty-two memory approaches profiled in this section, feature by feature: the keyless session-memory server, the two file-rooted members (the file convention and the knowledge base that productizes it), the MCP-native markdown knowledge base, the session-compression plugin, the retroactive transcript-indexing binary, the session-mined personal working profile, the cross-model episodic memory engine, the markdown-canonical local runtime, the memory-first harness, the temporal local-first engine, the four memory APIs, the memory agent that manages the others, the graph-plus-SQL layer, the reversible-compression plugin, the self-hostable graph pipeline, the self-hostable memory OS, the agent-curated memory wiki, the portable memory format, the single-file frame format, the provenance-first personal brain, the learning-from-feedback engine, the cross-harness shared-engram engine, the screen-capture timeline, the belief-graph memory layer, the verbatim pull-only recall index that publishes to the Hub, the OKF-standard knowledge-bundle implementation, the context database, and the agent-maintained documentation brain.

**For coding agents I would start with plain files and not buy any service on benchmark claims, because the only memory problem files cannot solve at any price is contradiction over time, and Zep is the only vendor whose architecture faces it head on.**

## Reading the matrix

**The Kind row is really an architecture row: the non-convention members each put memory in a different place, beside the agent as a plugin (claude-mem) or a cross-model engine (Engrim), inside the harness (Letta), beside it as an API (Mem0 or Supermemory), or under it as governed infrastructure (Zep), or over the whole machine as one shared server (agentmemory) or under every wired harness as one shared YAML store (PLUR) or as one append-only verbatim log the agents query only when they ask (Funes), deja skips the capture step by indexing the transcripts the harnesses already wrote, while Screenpipe records the screen itself, Memvid freezes memory into one file, LongMemory governs it in SQLite, EverOS keeps it in markdown files with indexes beside them, and the convention puts it in your repo, which Operator Memory productizes as an agent-maintained documentation brain and OKF Agent Memory formalizes as a knowledge bundle on Google's published OKF format.**
That placement decision drives every other row, from integration surface to lock-in.
**Basic Memory and memU stay on the repo side of that line and add a layer on top, a graph-and-search view or a cross-agent wiki, which is why their lock-in cells read low.**
**Memoryfields is the extremum on the same axis: it removes the architecture entirely by shipping memory as a spec'd data format, which is why its row is the cheapest and the thinnest at once.**

**The contradiction row is the only one with a clean winner, and it is the row I would weight most.**
Zep's bi-temporal invalidation marks old facts invalid instead of overwriting them; Mem0's April 2026 rewrite added entity linking and temporal retrieval, a convergence its own note reads as Zep validating the architecture first; Supermemory claims automatic resolution and expiry, but at README level, and the one independent run I found scored it below plain BM25 on LoCoMo at a matched budget; MemOS corrects through natural-language feedback rather than validity windows; Letta consolidates at sleep time; files just rot, and conflicting rules get resolved arbitrarily.

**The file column wins every row it appears in on price, and loses exactly two: cross-user memory and audit.**
Auto memory is machine-local and per-repository, so the moment memory must follow users across apps and machines, the free option drops out, which is the precise boundary where the services earn their keep.
Engrim is the second zero-cost column, and it loses the same two rows (audit partial, cross-user absent), which makes the free local options the natural set for personal memory; deja joins as the third, trading a capture step for retroactive indexing of what the harnesses already wrote, PLUR as the fourth, one YAML store that every wired harness itself reads and writes, and Funes as the fifth, a verbatim recall index the agents query only when they choose to.
Operator Memory and OKF Agent Memory are free the same way, markdown brains over your own git with no hosted tier at all.
Basic Memory and memU join the cheap-and-local side with working multi-file servers and adapters, but their cross-user stories are one user with a cloud add-on.

**Open source here does not mean what the license row suggests, and the self-host row is the correction.**
Letta's 25.0k-star repo is a landing page with the V1 server archived unsupported; Zep's self-hostable Community Edition is discontinued and only the Graphiti engine remains open; Mem0's benchmarked brain is the paid platform while the OSS SDK is directionally weaker.
**Cognee and Engrim are the exceptions the row now proves: Cognee's entire engine is Apache-2.0 with no paid-only core, and Engrim is MIT over a plain SQLite file, which is why their lock-in cells are the only lows among the services, with Basic Memory's markdown-local design reading the same way under an AGPL license.**
**The only column with no gap between what is open and what runs is the convention, because there is nothing to close.**

**Pricing spreads from zero to $104/month at entry, and the hosted services now bracket each other from both ends: Basic Memory's cloud is the cheapest first paid tier at $15, Mem0 and Supermemory both start at $19, claude-mem's restructured ladder begins at $30, and Zep at $104, roughly a 7x gap between cheapest and priciest first paid tier, and what the premium buys is governance (provenance, access control, compliance), not memory quality.**
Supermemory meters every layer in its own SM tokens; Mem0's $19 Starter undercuts the hosted field at the low end; Zep's credit metering prices the audit trail, not the tokens; MemOS now lists $19 and $286 tiers and runs both free during the launch promo, and Hindsight Cloud meters tokens with no fixed monthly fee.

## Choosing from the matrix

- Coding agent in one repo, one machine: write the AGENTS.md/CLAUDE.md pair, prune monthly, pay nothing.
- User-facing personalization across apps and thousands of users: Mem0, accepting a managed dependency.
- The same job with the engine runnable on your own disk and benchmark tooling included: Supermemory, after running its MemoryBench on your own workload.
- Facts change over time (preferences, roles, prices) and "why did the agent say that" needs an auditable answer: Zep.
- Always-on agents that must accumulate a self, or you want to hack on where memory is going: Letta, or steal its memory-block and sleep-time patterns into a harness you already run.
- Must self-host everything: Cognee (the whole engine runs on your backends), files, or Mem0 OSS, or Graphiti plus your own graph database if you can operate one.
- Memory across many users with flat billing instead of seats or credits: Cognee Cloud at $1.00 per 1M tokens processed.
- Solo builder on no budget: files, full stop; Zep's own note says the graph stack is heavy at small scale.
- One server shared by every coding agent you run, working before you configure any provider: agentmemory, rerunning its eval harness on your own sessions first.
- OpenClaw or Hermes agents that burn tokens on tool logs and need the trail kept: TencentDB Agent Memory, after rerunning its vendor benchmark table on your own sessions.
- Recall of what every agent on this machine already fixed, with no capture step to run: deja, one MIT binary over the transcripts on disk, after rerunning its benchmark scripts on your own history.
- A mined first draft of your own unwritten rules, receipts attached: Emulo, after reading its published 0-for-9 placebo page and running `emulo verify` on the result.
- A markdown-canonical local runtime with separate user and agent tracks for OpenClaw, Hermes, or DeepSeek Harness: EverOS, accepting a young, vendor-led dependency.
- One developer, multiple agent CLIs, one repo: Engrim, the only column that keeps one provenance-tagged store every CLI reads.
- Markdown notes in the Obsidian style that your agent grows into a knowledge graph through MCP: Basic Memory, free locally, $15/seat/mo for cloud sync.
- A research-grade belief layer scoring every memory with confidence and contradiction edges: Belief Context Graph, accepting zero releases and self-published benchmarks.
- Memory and skills that follow you across ChatGPT, Claude Code, and Cursor: memU, the wiki the agents curate themselves.
- Benchmark-first buyers who want receipts: Hindsight, the only member publishing per-run benchmark artifacts alongside named outside reproducers.
- Product agents on LangGraph or CrewAI stacks that want OSS episodic plus profile memory on their own databases: MemMachine, after running your own evaluation, since it publishes none.
- A fleet whose memory needs managing, not just storing (contradictions, expiry, pre-task briefs): Memanto, accepting a young vendor-led manager.
- One correctable brain across your own agents: GBrain, MIT and self-hosted, with sources on every page.
- A filesystem store for knowledge, memory, and skills together: OpenViking, accepting AGPL.
- One memory shared across Claude Code, Codex, Cursor, and OpenCode on one machine, in files you can read and git: PLUR, after running plur-bench on your own corpus before trusting the benchmark claims.
- Auditable recall of what was actually said across Claude Code, Codex, pi, and Hermes, publishable as a Hub dataset you own: Funes, after measuring with the recency half-life off, since the project's own A/B runs found its retrieval extras buy cost and not recall.
- OpenClaw, Hermes, or DeepSeek Harness agents with a local-first memory that can scale to a shared graph: MemOS.
- Memory that must follow you across machines and apps without a vendor: Memoryfields, with the caveat that the spec is a draft and its contradiction handling is a status flag rather than a temporal model.
- An offline single-file memory archive with working indexes: Memvid, after verifying its benchmark claims on your own corpus, and with the quiet-train caution attached.
- Temporal and governed memory you administer yourself: LongMemory, the only open engine here with point-in-time truth, accepting a young dependency.
- Agents that should know what you did on this machine, with a capture-everything budget and a paid license for work: Screenpipe.
- Documentation as the memory, maintained by the harness you already run: Operator Memory, reading its comparison doc first, since the project rejects benchmarks outright and offers prose instead.
- Memory on a published standard format rather than a vendor's store: OKF Agent Memory, accepting that every published number is latency-side and self-measured.
